# Multi-model cooperation kit

## What this is
`delegate`, a Rust CLI that hands task specs to worker models (Pi, Codex, Claude Code,
OpenCode, Gemini) in sandboxed git worktrees, checks and merges their work; plus the project
templates and skills it installs. Users: developers who lead with Claude Code and want their
other models doing the implementation.

## Source of truth
- **Code and tests are the truth.** If any doc conflicts with the code, follow the code
  and list the conflict under "Doc conflicts" in your REPORT.md.
- Why things are the way they are: `docs/decisions/` (append-only, newest wins).
- What we're working on now: `PLAN.md`.
- What users need: `evals/jobs.md` and `evals/scenarios/`.

## Commands
- Check all before finishing: `scripts/check` (Python eval-infrastructure tests;
  clippy, all + pedantic as errors; Rust unit tests)
- User scenarios: `evals/run S004` (one), `evals/run fast` (all fast ones)
- Rust is pinned in `delegate/mise.toml`; run cargo through `mise exec --`.

## Layout
- Task state lives under `~/.local/share/delegate/checkouts/`, found by the checkout's id
  in the git common dir (linked worktrees share it; `DELEGATE_HOME` overrides it).
- `delegate/src/` — the CLI: `commands.rs` (subcommands), `config.rs`, `harness.rs` (worker
  commands, bwrap), `task.rs` (state), `status.rs` (live state, `status`), `events.rs`
  (worker stream adapters), `watch.rs`, `wait.rs`, `statusline.rs`, `spec.rs`, `prompts.rs`,
  `init.rs`, `upgrade.rs` (`delegate upgrade`, `.delegate-kit.toml`), `blocks.rs` (managed
  blocks in `AGENTS.md`/`CLAUDE.md`), `quota.rs` (account
  quota readers, runway, `delegate quota`), `sha256.rs`
- `delegate/templates/` — spec/report templates; `project/` is what `delegate init` installs;
  `kit-history.txt` lists every earlier kit (generated by `scripts/kit-history`)
- `prototypes/herdr-observer/` — opt-in headless attribution/status adapter spike; not a native UI or production ownership API
- `evals/` — user scenarios with executable checks; `evals/lib/` shared setup and stand-in workers
- `evals/tests/` — standard-library tests of check infrastructure, run by `scripts/check`;
  these are not live scenario verdicts
- `.agents/skills/` — shared kit skills; `.claude/skills/{delegate,distill,evaluate}` link here
- `.claude/skills/delegate-pane/` — the Claude Code side pane mod (`claude plugin test <dir>`)
- `evals/lib/streams/` — recorded worker streams for checks; their `.steps` files are written by the lead, never by an adapter's author

## Conventions
- Errors go through `anyhow` with `bail!`/`context`; messages say what to do next.
- `unsafe` is forbidden; no `unwrap()` outside tests.
- `delegate/templates/project/` mirrors the kit files at the repo root (`.agents/skills/`,
  `.claude/skills/` links and pane, `evals/run`, templates): change both together, then run
  `scripts/kit-history` (a unit test fails until you do).

## Never
- Add dependencies without the spec saying so.
- Change public APIs, schemas or migrations outside the spec's scope.
- Change a scenario's `scenario.md` or `check` to make it pass.
- Commit secrets, push, deploy, or touch CI config unless the spec says so.

## The lead's role in this project
If `.task/SPEC.md` exists, you are a delegated worker: skip this section and do only the spec.

The lead handles: discussion, design, contracts, task breakdown, review and merge.
Implementation goes to other harnesses through `/delegate` unless the task is ambiguous,
architectural, security-sensitive, or a debugging hunt with an unknown cause.

- Split plans into waves of tasks touching different files, and start each wave together.
- End a design discussion with `/distill`: record decisions, update `PLAN.md`, nothing else.
- A feature's user scenarios come before its specs: `/evaluate feature`. A reported bug
  becomes a failing scenario first: `/evaluate bug`.
- Review delegated work against the spec's Acceptance section and `git diff`,
  not the delegate's transcript.
- During review, ask "did this change make any doc false?" and fix it on main right after
  the merge. Never commit on a task branch: fixes go back to the worker as another round.
- Every delegated task ends in `delegate merge` or `discard`; run `delegate list`
  before ending a session so no task state is left behind.
<!-- delegate:end lead -->

- Use one session per phase, hand off in `PLAN.md`, then suggest `/clear` or a new session.
