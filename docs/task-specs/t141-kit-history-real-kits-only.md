# Task t141: Kit history lists only kits that shipped

size: small

## Goal
`delegate/templates/kit-history.txt` must be exactly what `scripts/kit-history` generates
from git history. t140 hand-added an entry (id `6b531f9317d6`): the current kit's skills
in the retired `.claude/skills/<name>/SKILL.md` layout. No project ever had that kit. It
was added only because two upgrade tests write *today's* skill bodies at the legacy path
and need some kit to recognise them. Any later skill edit would need another fake entry.
Fix the tests instead: build the legacy layout they need inside the test, and keep the
embedded history to real kits only.

## Context (read these, nothing more)
- `AGENTS.md` (Conventions: the kit-history rule)
- `scripts/kit-history` (header comment)
- `delegate/src/upgrade.rs`: `history()`, `current()`, `identify`, and the tests that call
  `old_skill` (e.g. `migrated_skills_do_not_reinfer_retired_entries_from_head`,
  `old_skill_pointers_and_files_preserve_legacy_evidence`)

## Scope
- In: `delegate/src/upgrade.rs` (`#[cfg(test)]` code only),
  `delegate/templates/kit-history.txt` (regenerated by `scripts/kit-history`, never
  edited by hand)
- Out: non-test code in `upgrade.rs`, `scripts/kit-history`, `init.rs`, kit files,
  `scripts/check`

## Contract
- Production behaviour doesn't change. Recognising a real older kit (any entry
  `scripts/kit-history` emits) works as before.
- Tests that need "a project still on the legacy skill layout" build that kit in the
  test, for example by adding to `history()` a copy of `current()` with skills
  remapped to `.claude/skills/<name>/SKILL.md`. They don't depend on an entry in
  the embedded file. Each affected test still checks what it checked before. Don't
  weaken assertions and don't delete tests.
- Add one unit test: no kit in `history()` has an id equal to `current().id`, and none
  has the same file hashes as the current kit under remapped paths. This catches a
  fake companion being added again.

## Acceptance
- [ ] `scripts/kit-history && git diff --exit-code -- delegate/templates/kit-history.txt`
- [ ] `! grep -q 6b531f9317d6 delegate/templates/kit-history.txt`
- [ ] `scripts/check`

## Answers
1. (b). Split `upgrade()` into a private `upgrade_with_kits(..., kits: &[Kit])` and a
   public wrapper that passes `history()?`. This is the only non-test change allowed in
   `upgrade.rs`: no other behaviour or signature changes. No thread-local or
   `cfg(test)` code inside production functions. Both named tests keep exercising the
   full automatic upgrade path through the inner function. The legacy kit they pass
   must make `old_skill_pointers_and_files_preserve_legacy_evidence` independent of
   today's `distill`/`evaluate` bodies matching `b129c8e57f94`.
2. (a). Remap only the link entries, exactly the construction you verified reproduces
   `6b531f9317d6`'s `files`. Use the same helper to build the test kit for question 1.
3. (a). Exactly one entry has `current().id`. It is last and has `current().files`. No
   other entry equals the remapped map.
